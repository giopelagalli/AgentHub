# Daemon configs

A daemon config is the YAML file passed to `packages/node-daemon` (`tsx packages/node-daemon/src/main.ts <config.yaml>`). It tells the node daemon who it is, which hub to register with, and which model-serving processes to supervise on this machine — one entry per tier it serves. The daemon launches each `serving` entry's `cmd`, waits for it to come up on `port`, and registers the resulting endpoints with the hub so the gateway can route agent traffic to them.

`DaemonConfig` fields: `node: { name: string; arch: string }`, `hub: string`, `advertiseHost?: string`, `heartbeatMs?: number`, `serving?: ServingConfig[]`, `jobTypes?: JobType[]`, `workspaceRoot?: string`, `claimIntervalMs?: number`, `browser?: { enabled: boolean; port?: number; display?: string; headless?: boolean }` (the shared browser server — Mac mini only, see `deploy/macmini/README.md`). `ServingConfig` fields (one per entry in `serving`): `tier: Tier`, `model: string`, `port: number`, `maxStreams: number`, `cmd: string[]`. `serving` may be empty or omitted (it defaults to `[]`), but the daemon must declare at least one capability — a non-empty `serving`, a non-empty `jobTypes`, or `browser.enabled: true` — or `loadConfig` throws `daemon config: no capability (serving, jobTypes or browser) declared`; a browser-only node (see `deploy/macmini/README.md`) is the main case that needs no `serving` at all. `configs/dev-node.yaml` is a working example that serves both tiers from the mock OpenAI server (`packages/mocks/src/serve.ts`) instead of a real model. Real nodes replace `cmd` with their own serving-stack launch command (e.g. a `vllm serve ...` invocation or a wrapper script around it) — everything else about the config stays the same.

`jobTypes` lists which `JobType`s (`'llm-session' | 'video-gen' | 'shell-task' | 'browser-lease'`) this node's job runner claims from the hub queue; omitted or empty means the node serves model tiers only and runs no job runner. `workspaceRoot` is the directory shell-task jobs run in (defaults to `<cwd>/workspace`); `claimIntervalMs` is how often the job runner polls the hub for claimable jobs (defaults to `1000`). See `configs/spark.yaml`, `configs/amd.yaml`, `configs/macbook.yaml` for real-node examples.
